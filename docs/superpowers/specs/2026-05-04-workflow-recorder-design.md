# 工作流记录器 — 技术设计文档

> 基于飞书 + AI 网关的知识沉淀与内容生产系统

## 概述

服务于 WayToAGI 的 AI 咨询业务。当顾问在服务客户过程中解决新的技术场景时，将过程记录、归类、沉淀为可复用的知识资产，并自动产出自媒体内容。

核心理念：**顾问正常聊天工作，AI 在后台整理。**

## 两条路径（核心设计原则）

### 路径 1：记录 — 纯飞书能力，零额外成本

顾问的日常聊天和文档操作完全在飞书内完成，不需要任何额外操作：
**Phase 1 方式：** 顾问手工操作——在群聊中将有价值的信息"转存到知识库"（飞书原生功能），或直接创建飞书文档。不写额外代码。

**Phase 3 可优化：** 飞书机器人监听群聊，自动存到知识库（需要机器人权限，Phase 1 暂不做）。

所有原始内容天然在知识库中。

**不做：** 实时拦截每条消息、实时 AI 分析、webhook 中转

### 路径 2：聚合 — AI 网关定时后处理

AI 网关定时扫描知识库中的新增内容，做 AI 驱动的后处理：
- 批量处理，非实时
- 提取结构化摘要和标签
- 归类到对应客户/场景
- 自动识别可模板化的模式

## AI 网关模块设计

### 1. 扫描器

- **触发方式：** GitHub Actions 定时（`cron: 0 2 * * *`），也支持手动触发
- **增量检测：** 记录上次处理时间戳（存于飞书多维表格的一行配置记录中）
- **产出：** 待处理文档列表

### 2. 处理器（核心模块）

对每条新记录，调用 Claude API 做三件事：

| 操作 | 输入 | 输出 |
|------|------|------|
| 分类 | 文档全文 | 场景类型、所属客户、涉及工具 |
| 摘要 | 文档全文 | 100-200 字结构化摘要，含问题和解决方案 |
| 打标 | 文档全文 + 已有标签库 | 自动标签列表 |

输出结构：
```json
{
  "doc_id": "xxx",
  "title": "客户A_LLM输出格式稳定性",
  "summary": "客户A的LLM输出格式不稳定，通过few-shot+JSON schema约束解决",
  "tags": ["客户A", "LLM调优", "JSON Schema", "few-shot"],
  "scene_type": "模型输出稳定性",
  "is_novel": true,
  "similar_records": [],
  "execution_steps": [
    "分析错误格式的模式",
    "设计JSON Schema约束输出格式",
    "添加3个few-shot示例",
    "测试验证通过"
  ]
}
```

### 3. 去重引擎

- 对比多维表格中已有记录
- 新场景 → 新增记录
- 已有方案变体 → 标记为复用，更新复用次数
- 复用次数越高的场景，越优先被提炼为 Playbook

### 4. 报告生成器

基于一段时间内的记录聚合，自动生成：

| 输出 | 频率 | 目标 | 通路 |
|------|------|------|------|
| 日报 | 日 | 团队内部 | 飞书文档推送到群 |
| 周报 | 周 | 团队 + 管理层 | 飞书文档 |
| 小红书图文 | 周 | 公域获客 | → content_creator skill → 审核 → 发布 |
| 抖音口播稿 | 周 | 公域获客 | → content_creator skill → 审核 → 发布 |

自媒体内容流程：
```
AI 网关提取本周案例 → 脱敏处理
  → content_creator skill 格式化（通过 lark-cli 或直接调 API）
    → 小红书：标题(话题+情绪公式) + 正文 + 搜索关键词布局
    → 抖音：口播稿 + 分镜建议
  → 顾问审核（在飞书文档中审阅）
  → publish_to_platforms 发布
  → 互动数据回传 → AI 网关了解哪些案例受欢迎
```

## 飞书数据模型

### 知识库目录结构

```
WayToAGI 知识库空间
├── 📁 原始记录（按客户/日期自动归档）
├── 📁 AI 整理摘要（AI 网关生成的标准化文档）
├── 📁 Playbook（已被模板化的最佳实践）
├── 📁 自媒体素材（脱敏后可公开）
└── 📁 日报/周报
```

### 多维表格结构

| 字段 | 类型 | 说明 |
|------|------|------|
| 记录 ID | 自动编号 | 唯一标识 |
| 标题 | 文本 | 场景标题（AI 生成） |
| 摘要 | 文本 | 结构化的场景摘要 |
| 客户 | 单选 | 所属客户 |
| 行业 | 单选 | 传媒/广告/出版/电商/金融... |
| 场景类型 | 单选 | 模型调优/知识库搭建/流程改进/提示词工程... |
| 涉及工具 | 多选 | GPT/Claude/飞书AI/Stable Diffusion... |
| 标签 | 多选 | 自动打标 |
| 复用次数 | 数字 | 被复用的次数 |
| 是否模板化 | 复选框 | 标记为可复用的 playbook |
| 原始文档 | 文档链接 | 关联到飞书知识库中的原始文档 |
| 创建日期 | 日期 | 自动 |
| 状态 | 单选 | 待整理/已整理/已模板化 |

## 部署方案

### GitHub Actions

```yaml
# .github/workflows/ai-gateway.yml
name: AI Gateway Daily Pipeline
on:
  schedule:
    - cron: '0 2 * * *'
  workflow_dispatch:

jobs:
  process:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'
      - run: pip install -r requirements.txt
      - run: python ai_gateway.py
        env:
          FEISHU_APP_ID: ${{ secrets.FEISHU_APP_ID }}
          FEISHU_APP_SECRET: ${{ secrets.FEISHU_APP_SECRET }}
          CLAUDE_API_KEY: ${{ secrets.CLAUDE_API_KEY }}
```

### 状态持久化

- 运行时间戳存于飞书多维表格（一行配置记录）
- 每次运行开始读时间戳，结束写时间戳
- 无需额外数据库

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 定时执行 | GitHub Actions | 零运维，免费额度够用 |
| 编程语言 | Python | 与现有 content_creator 一致 |
| LLM | Claude API | 摘要/分类质量好 |
| 飞书 SDK | lark-cli + 飞书 Python SDK | 操作知识库/文档/多维表格 |
| 状态存储 | 飞书多维表格 | 无需额外数据库 |

## 核心伪代码

```python
def run_daily_pipeline():
    # 1. 读取上次处理时间
    last_run = get_last_run_timestamp()
    
    # 2. 扫描知识库增量
    new_docs = feishu_wiki.list_updated_docs(since=last_run)
    
    for doc in new_docs:
        # 3. LLM 处理
        content = feishu_doc.read_content(doc.id)
        result = llm.process(content, prompt=PROCESS_PROMPT)
        
        # 4. 写回多维表格
        feishu_base.create_record(result)
        
        # 5. 创建 AI 摘要文档
        feishu_doc.create_summary_doc(result)
    
    # 6. 生成报告
    generate_reports(new_docs, processed)
    generate_content_for_social_media(processed)
    
    # 7. 更新时间戳
    save_last_run_timestamp(now)
```

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| 知识库增量检测不准 | 用飞书文档的 `update_time` 字段，多次采样取最新 |
| LLM 摘要质量不稳定 | 设计带格式约束的 prompt，输出 JSON 格式强制结构化 |
| 自媒体内容审核缺失 | 所有内容走"AI 生成 → 顾问审核 → 发布"流程，不自动发布 |
| 飞书 API 限频 | 每次处理间隔 100ms，扫描限制每次 50 条 |
| 多维表格行数上限 | 飞书多维表格单表 50000 行，Phase 1 足够 |
